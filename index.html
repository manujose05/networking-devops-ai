Phase 1

Networking Fundamentals

0%

7-layer model that describes how data travels across a network.

LayerNameExample
7ApplicationHTTP, DNS, FTP
6PresentationTLS/SSL, JPEG
5SessionLogin sessions
4TransportTCP, UDP
3NetworkIP addresses
2Data LinkMAC addresses
1PhysicalEthernet, WiFi
Focus first on layers 3, 4, and 7 — you'll use them the most.

Every device needs an IP address — like a home address for data packets.

  • Private: 192.168.x.x — inside your home/office
  • Public: 8.8.8.8 — visible on the internet
  • IPv4: 32-bit, ~4 billion addresses
  • IPv6: 128-bit, practically unlimited

Subnets: 192.168.1.0/24 — /24 means 254 usable hosts. /16 = 65,534 hosts.

CIDR notation: the number after / tells you how many bits are the "network" part.

DNS translates human-readable names into IP addresses.

  • A record: google.com → 142.250.80.46
  • CNAME: www.google.com → google.com
  • MX record: Mail server for a domain
dig google.com
nslookup google.com

Common ports:

  • 22 = SSH
  • 80 = HTTP
  • 443 = HTTPS
  • 3306 = MySQL
  • 5432 = PostgreSQL
  • 6379 = Redis
# Check your IP address
ip addr show

# Test connectivity
ping 8.8.8.8

# Trace packet route
traceroute google.com

# DNS lookup
dig google.com
nslookup google.com

# Check open ports
ss -tulpn

# View connections
ss -s

# Firewall status
ufw status
iptables -L
Phase 2

DevOps & Cloud Networking

0%

The journey from code to production:

Developer writes code
      ↓
Git commit + push
      ↓
CI/CD Pipeline (build + test)  ← GitHub Actions, Jenkins
      ↓
Docker container built
      ↓
Deployed to Cloud (AWS/Azure/GCP)
      ↓
Load Balancer distributes traffic
      ↓
Users access via DNS

Spreads incoming traffic across multiple servers so no single server is overwhelmed.

              ┌── Server 1
Internet → LB ├── Server 2
              └── Server 3
  • Round-robin: Rotate through servers evenly
  • Least connections: Send to least busy server
  • IP hash: Same user always hits same server

Tools: Nginx, HAProxy, AWS ELB, Cloudflare

VPC (Virtual Private Cloud) is your own isolated network inside AWS/Azure/GCP.

  • Public subnet: Has internet access — put load balancers here
  • Private subnet: No direct internet — put databases and app servers here
  • Security Groups: Virtual firewall for EC2 instances
  • NACLs: Subnet-level firewall rules
Golden rule: databases should NEVER be in a public subnet.

Docker creates virtual networks so containers can talk to each other.

# List networks
docker network ls

# Create a network
docker network create my-app-network

# Run containers on same network
docker run --network my-app-network --name db postgres
docker run --network my-app-network --name app myapp
# 'app' can reach 'db' by hostname 'db'
  • Pod: Smallest unit — gets its own IP
  • Service: Stable DNS name + IP in front of pods
  • Ingress: Routes external HTTP(S) to services — like a smart load balancer
  • CNI: Plugin that handles pod-to-pod networking (Calico, Flannel, Cilium)
# Expose a deployment as a service
kubectl expose deployment myapp --port=80 --type=LoadBalancer

# Check services
kubectl get services
kubectl get ingress

The three pillars of observability:

  • Metrics: Numbers over time — CPU, memory, request rate (Prometheus)
  • Logs: Text records of events (ELK Stack, Loki)
  • Traces: Track a request across microservices (Jaeger, Zipkin)

Stack: Prometheus (collect) → Grafana (visualize) → Alertmanager (alert)

Phase 3

AI Use Cases in Networking & DevOps

0%

AI monitors your infra and detects problems before users notice.

  • Anomaly Detection: AI learns normal traffic — alerts on deviations
  • Predictive Failure: Predicts disk failure 48 hours in advance
  • Root Cause Analysis: Finds which of 100 microservices caused the slowdown

Tools: Dynatrace, Datadog, Splunk, New Relic

Normal:    Login from NY, 9am, downloads 50MB
Anomaly:   Login from unknown country, 2am, downloads 50GB
           → AI flags + blocks automatically
  • IDS/IPS: Intrusion Detection/Prevention using AI models
  • DDoS Detection: Distinguish real traffic from attack floods
  • UEBA: User behavior analytics — catches insider threats

Tools: CrowdStrike, Darktrace, AWS GuardDuty, Palo Alto Cortex

Replacing manual CLI-typing with AI-driven config management.

  • NL to Config: "Block all traffic from X" → AI generates firewall rules
  • Drift Detection: Compares actual vs intended config, flags differences
  • Auto-remediation: Detects and fixes misconfigs without humans

Tools: Cisco DNA Center, Juniper Apstra, Ansible + LLM

  • SD-WAN: AI routes traffic on the best path in real time
  • QoS: AI prioritizes video calls over file downloads automatically
  • CDN optimization: AI predicts what content to cache where

Tools: Cloudflare, Fastly, AWS Global Accelerator

Engineer → Slack: "Why is prod slow?"
LLM Bot  → queries Datadog + K8s + logs
LLM Bot  → "Pod myapp-3 has OOMKilled 5x.
            Memory limit 512MB but using 800MB.
            Recommend increasing limit."
  • LLM reads runbooks → auto-responds to alerts
  • AI generates Terraform/K8s YAML from natural language
  • AI-assisted incident postmortems
